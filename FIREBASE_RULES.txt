# Firebase Rules

Use `firestore.rules` and `storage.rules` as the deployable source of truth.
This file is kept as a quick reference for the current security model.

## Firestore

- `gardens`: authenticated users can create only with an active server-written entitlement. Owners can update/delete. Owners and collaborators can read.
- `photos`: owners and collaborators can read/create through an existing garden; only the garden owner or the uploader can delete; updates are denied.
- `users`: profile documents are private to the authenticated user.
- `entitlements`: users can read only their own entitlement; client writes are denied.
- `orders` and `commerce`: client reads/writes are denied; server APIs use service account access.
- Unknown collections are denied.

## Storage

- Photos live under `gardens/{gardenId}/photos/{uploaderId}/{fileName}.webp`.
- Owners and collaborators can read objects for gardens they can access.
- Uploads require an authenticated collaborator/owner, WebP content type, a matching uploader path, and a maximum size of 10 MB.
- Garden owners can delete any garden photo object; uploaders can delete their own objects.
- Unknown paths are denied.
